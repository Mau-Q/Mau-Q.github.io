统一框架

后训练的本质是：通过不同形式的反馈，重新调整模型对不同回答的概率。

假设给模型一道题：

6 ? 2=126\ ?\ 2 = 126 ? 2=12，应该填什么运算符？

模型可能生成：

A：6 + 2 = 8，所以答案是 +

B：6 × 2 = 12，所以答案是 ×

C：绕了很久，最后答 -

SFT、DPO、PPO、GRPO 的根本区别，不是模型结构不同，而是：你究竟怎样告诉模型 B 比其他答案好。

SFT：直接告诉模型答案

训练模型时，直接给模型答案：

然后让模型提高生成标准答案的概率。就像“老师把解题过程写在黑板上，学生照着学。”

所以 SFT 擅长的是模仿，但有一个问题，模型学习的是“像不像”，而不是“对不对”。

DPO：告诉模型“这个比那个好”

训练数据变成：

让模型学习 P(Chosen)>P(Rejected)P(\text{Chosen}) > P(\text{Rejected})P(Chosen)>P(Rejected)。于是 DPO 不像 SFT 让模型模仿生成答案的过程，而是告诉模型这两个回答里，我更喜欢前者。

PPO：模型做题，做完打分

接下来进入强化学习，PPO的流程变为：

模型在训练过程中不只是被动接受输出，也进行回答。比如模型生成 答案 +，reward = 0；答案 *，reward = 1。这样模型就能学习第二种回答更应出现。

GRPO：

GRPO 是 DeepSeekMath 提出的 PPO 变体，后来 DeepSeek-R1 大规模采用：

也是每一个回答进行 reward 评分，但是不是看绝对 reward ，而是看每一个回答相对于同组的其他回答怎么样。比如组内 reward为：

R=[0, 1, 0.8, 0.2]R=[0,\ 1,\ 0.8,\ 0.2]R=[0, 1, 0.8, 0.2]

平均 ：Rˉ=0.5\bar R=0.5Rˉ=0.5，那就可以让模型知道第 2,3 个回答比同组平均水平好，而第 1,4 个回答相反。

SFT（Supervised Fine-Tuning，监督微调）

先来看 SFT Loss公式：

LSFT=−∑t=1Tlog⁡Pθ(yt∣x,y<t)\mathcal L_{\mathrm{SFT}} = -\sum_{t=1}^{T} \log P_\theta(y_t\mid x,y_{<t})LSFT​=−t=1∑T​logPθ​(yt​∣x,y<t​)

xxx 是问题，y<ty_{<t}y<t​ 是模型产生的上下文，yty_tyt​是模型要预测的 token ，θ\thetaθ是模型参数，于是 SFT 的目的就是在给定上下文的情况下最小化生成下一个 token 的 Loss，使得其和标准答案一致。

那为什么 SFT 不是背答案呢？因为训练集中可能会反复出现可泛化（generalization）的能力，比如：→ 分解条件→ 建立关系→ 计算→ 验证→ 答案，那模型就可能学习到解题的模式。这其实和普通的监督学习一样，比如训练猫狗分类器，不是希望模型背答案，而是让模型提取图片中可泛化特征。

如果是CoT-SFT，会把模型中间 reasoning token 也计算 loss，相比于一般的 SFT，模型不仅学习正确答案是什么，还学习了中间正确的推理过程。

但是注意，SFT 并不是让模型学会推理，假设训练数据是Question->Step 1->Step 2->Step 3->
Answer，模型只是学习提高生成每一个Step的概率，但是它并不知道为什么要这个Step，这个Step是否必要，是否正确。

所以这就引发了思考：SFT 到底让模型学会了什么？比较肯定的是，模型学习到了reasoning format和reasoning strategy。前者是让模型知道推理格式怎么组织，比如思考时用<think>标签，回答时用<answer>，也学会了比如要分布推理的方法；后者让模型学习对应具体问题应该怎么具体分析，比如对于数学问题，怎么进行具体的分布推理：分析、回溯、验证等方法。

但是 SFT 是否让模型学习了新能力？这个争议比较大。在 LIMA 中，作者提出Superficial Alignment Hypothesis：模型在预训练阶段已经获得了大量能力，SFT 更多的是教模型把这些能力以符合用户偏好的方式表现出来。但是不能把这个理解为 SFT 没让模型学习到新能力，因为在反向传播的过程中模型参数改变，而这些改变可能会影响模型能力。所以多少是模型本来就有的能力，多少是学习的能力，这个是在 SFT 阶段值得思考的。

这样我们知道了 SFT 主要学习的是Imitation，主要让模型学习特定的解题路径，但为什么对，还有没有其他方法，这是没有学习的。所以自然地想到用 RL 让模型自己探索。

RL 训练的本质是：
at∼πθ(⋅∣st)a_t\sim\pi_\theta(\cdot|s_t)at​∼πθ​(⋅∣st​)

意思是：在时刻 ttt，智能体根据当前状态 sts_tst​，从参数为 θ\thetaθ 的策略 πθ\pi_\thetaπθ​ 所定义的概率分布中，采样得到动作 ata_tat​。

Policy，也就是 πθ(⋅∣st)\pi_\theta(\cdot|s_t)πθ​(⋅∣st​)，其实就是LLM中的Pθ(next token∣context)P_\theta(\text{next token}\mid\text{context})Pθ​(next token∣context)，比如对于给定上下文，模型可能预测P(A) = 20%，P(B) = 30%，P(C) = 50%，这整个分布就是Policy，RL 就是要改变模型参数从而改变这个概率分布。

前面说到Reward大致怎么给出，一般来说正确为 1，错误为 0。所以 RL喜欢可验证答案，而不是无法评分的答案。

如果只给最终的答案Reward，我们就无法知道中间的推理过程哪些 token 是值得模型学习的，所以这就需要Credit Assignment，也就是最后的正确回答需要把功劳分给哪些行为。PPO 为了解决这个问题，要引入Value 和 Advantage。

Value定义为：V(st)V(s_t)V(st​) ，直觉是：现在已经生成到这里，根据经验，最终预计能拿多少 reward？比如好的方向得到V(s)=0.8V(s)=0.8V(s)=0.8，不好的方向得到V(s)=0.2V(s)=0.2V(s)=0.2。

Advantage最简单的理解是： A≈R−V(s)A \approx R-V(s)A≈R−V(s)，表示实际结果比预期结果好多少。比如之前判断V(s)=0.2V(s)=0.2V(s)=0.2，但是最后得到Reward=1Reward = 1Reward=1那A=0.8>0A = 0.8 > 0A=0.8>0，说明模型做的比预期好，需要强化，所以反过来A<0A <0A<0 就要避免。

这样有这一个简单的模型：A≈R−V(s)A \approx R-V(s)A≈R−V(s)，我们就能控制模型在推理过程中需要强化哪些行为。比如 2个问题最后 Reward = 1，简单的问题 A = 0.1，复杂问题 A = 0.9，我们就知道了需要强化的具体方向。

最基本的思想是：

GRPO（Group Relative Policy Optimization，组相对策略优化）

在 PPO 中，相对于 SFT 需要进行很多额外的计算，最关键的是计算A≈R−V(s)A \approx R-V(s)A≈R−V(s) 通常需要一个额外的模型，称作Value/Critic Model，这个模型也需要很大的神经网络。而既然计算Value就是定义一个比较标准，那 GRPO 就使用同一个问题产生不同回答，这样就可以得到比较标准，从而节省了计算资源。

比如对于同一个问题，使用 GRPO 生成多个回答：

{o1,o2,…,oG}\{o_1,o_2,\dots,o_G\}{o1​,o2​,…,oG​}

例如:

这样就得到了每一个回答在同组的表现怎么样，这就是Group Relative 。

最简单的比较标准就是计算同组Reward的平均值，把每个回答的Reward减去平均值，那我们就知道了o2,o3o_2,o_3o2​,o3​ 的回答较好。在实际计算中，还会把最后结果除以标准差做标准化统一训练尺度。于是：

Ai=Ri−mean⁡(R)std⁡(R)A_i=\frac{R_i-\operatorname{mean}(R)}{\operatorname{std}(R)}Ai​=std(R)Ri​−mean(R)​

所以 GRPO 和 PPO 一样，都是为了知道这次rollout是值得鼓励还是抑制。

利用 GRPO 算完Advantage之后，还是和 PPO一样进行Policy Gradient，所以 GRPO其实是PPO的变体，只是改变了计算Advantage的方式。

如果我们只对整个回答计算Reward，也就是典型的Outcome Supervision GRPO，同一回答所有 token 的 Advantage 相同，那我们就不知道咋推理过程中那些步骤作用大，哪些步骤没有作用，所以这适合只需要粗粒度反馈的任务，比如数学、代码等容易自动验证的任务。当然，为了解决这个问题，还有Process Supervision GRPO进行细致评价，同时代价当然也就更大。

但 GRPO也有局限：如果同组回答的Reward都差不多，那模型的有效学习信号就非常弱。比如所有回答都是错误的，Reward都未 0，那模型就很难学习，所以训练前的准备工作，训练方式也很重要。

DPO（Direct Preference Optimization，直接偏好优化）

前面 3 种方法走了 2 条线：

SFT：模仿标准答案\text{SFT：模仿标准答案}SFT：模仿标准答案 PPO/GRPO：自己生成答案，再根据 reward 优化\text{PPO/GRPO：自己生成答案，再根据 reward 优化}PPO/GRPO：自己生成答案，再根据 reward 优化

而 DPO 走了另外一条线：直接给模型一对回答，并告诉模型谁好谁坏：

一般表示为：(x,yw,yl)(x,y_w,y_l)(x,yw​,yl​)，其中：x=prompt,yw=winner / chosen,yl=loser / rejectedx = prompt,y_w=\text{winner / chosen},y_l=\text{loser / rejected}x=prompt,yw​=winner / chosen,yl​=loser / rejected。

那为什么需要这种“偏好”而不是像 SFT 一样告诉模型答案呢？因为现实中有很多问题难以得到所谓的“标准答案”，也难以计算Reward，比如很多alignment 问题：

哪个回答更有帮助？

哪个推理过程更合理？

但是这种问题我们很容易判断哪个回答更好：

= 340 + 68

答案都是正确的，但我们可以告诉模型 B 答案更好。

其实在 DPO 之前， RLHF 就使用了这种偏好对，但类似 PPO的训练方法还需要进行计算Reward，在用 PPO 将其最大化使得最后的生成分布更符合偏好的答案。那既然最后目的是生成偏好的答案，于是DPO就绕过了中间的计算和 PPO。

RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）

先来看经典的 RLHF，有：

现在就可以计算Loss了，由于有winner 和 loser两种类别，用二分类交叉熵（Binary Cross-Entropy，BCE）：

这就得到了 DPO 的核心Loss。

所以DPO的关键贡献是：把原来需要强化学习解决最大化Reward的问题，转换成用最优 Policy 相对于 Reference Policy 的概率比来表示Reward，把原本的奖励最大化问题转化为可直接通过偏好数据优化的分类目标，从而无需显式训练 Reward Model，也无需执行 PPO 等强化学习优化。

其实都是在计算当前chosen/reject的输出概率相对于reference model的比。我们希望这个差距越大越好。

那为什么 DPO 不直接算P(yw)>P(yl)P(y_w)>P(y_l)P(yw​)>P(yl​) 而是作“比”呢？因为可能对于reference model，chosen本来就比reject更难出现，所以 DPO 不要求最后P(yw)>P(yl)P(y_w)>P(y_l)P(yw​)>P(yl​)，而是chosen提高的比例大于reject提高的比例。所以reference model相当于提供了一个“锚点”。这就是为什么 DPO 不能简单的：chosen 做 SFT
