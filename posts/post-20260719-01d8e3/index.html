合适 > 优秀

最近更新：2026-07-19   |   字数总计：374   |   阅读估时：1分钟

最近在高强度 vibe coding 一周后，我越来越觉得虽然 Codex 功能强大，但是它无法把握什么是合适的。

在我们不需要动手写一行代码，甚至不需要怎么思考（这一周我尝试过让 GPT 规划路线，写提示词，理解 Codex 结果，形成了构建项目的闭环）时，我们不需要懂代码，但是我们必须懂怎么让 Codex 实施是合适的。

在这一周，我发现一个问题，Codex 和 GPT 经常把任务做的复杂化，虽然可能是正确的，但是对于项目可能不合适：在技术上过于困难，Codex 可能也无法有效完成；在时间上也做了比较多无用功。

虽然我也做了一些努力：用 harness 约束 Codex，用提示词规则约束 GPT，但是效果还是不怎么理想。客观上 harness 和提示词规则可以继续完善，但是我必须参与到这个项目中来，阅读 Codex 每行的思考，并且在GPT 辅助规划路线时也要进行理解学习。这样才能总体把握，避免 GPT 和 Codex 因为某个问题而过于纠结而浪费时间，甚至最后项目都不是很完整。导致虽然在某些功能上很强大，但是基础的流程都没有实现。

所以我认为在 vibe coding时，项目的流程完整性优先，质量优化其次。
